# NOTES.md — codebase map

Working notes for whoever is in this repo, including future-me after a few
months away. `CLAUDE.md` says *what was decided and why* (product rules,
trade-offs, things not to do). This file says *where the code is and how it
fits together*.

If you are new to TypeScript / Next.js, read **`ONBOARDING.md`** first — it
explains the language and framework concepts using this repo's own files as
the examples. Come back here for the map.

---

## 1. The 60-second version

A single visitor-facing Next.js site. Eight pages (home, work index, work
detail, about, contact, setup, gear, privacy) plus two API routes. There is no
CMS and no auth, and the only stored state anywhere is a single integer — the
footer's visit total. Everything the site shows is either:

- **hard-coded content** in `/content/*.ts` (typed objects — case studies,
  the setup and gear lists, the privacy policy), or
- **fetched at request time and cached for an hour** (the GitHub contribution
  graph), or
- **one number read from Redis** (the visit counter, §10), or
- **posted out** (contact form → Resend → inbox).

That means almost every page is statically renderable. The complexity in this
repo is not data — it is **motion, audio and layering**. Roughly 70% of the
non-obvious code exists to make animation behave itself (hydration, reduced
motion, autoplay policy, z-index stacking).

```
Visitor lands
  └─ app/layout.tsx renders on every route
       ├─ EntrySequence   (fullscreen overlay, once per browser session)
       ├─ Nav             (sticky header)
       ├─ {children}      ← the actual page
       ├─ Footer
       └─ AmbientAudio    (fixed pill, bottom-left)
```

### Tailwind v4 is different from v3

There is no config file. Look in `app/globals.css`:

```css
@import "tailwindcss";              /* replaces the three @tailwind directives */

:root { --accent: #22c55e; }        /* raw CSS variables */
```

two places**: a `:root` variable and a `--color-*` line in `@theme inline`.

## 4. Content: how a case study becomes pages

`content/case-studies/` is the single source of truth. Six files, one object
each, all shaped by the `CaseStudy` interface in `types.ts`:

```
types.ts             the interface
reisagri.ts         ─┐
roman-enterprises.ts │  one exported const each
bharatbhramana.ts    │
dropwatch.ts         │
gemora-storefront.ts │
gemora-dashboard.ts ─┘
index.ts             collects them into `caseStudies: CaseStudy[]`
                     + getCaseStudy(slug) + getFeaturedCaseStudies()
```

Consumers:

| Where | Uses |
|---|---|
| `/` home | `getFeaturedCaseStudies()` → `WorkShowcase` |
| `/work` | `caseStudies` (all six) → `WorkGrid` → `WorkCard` |
| `/work/[slug]` | `getCaseStudy(slug)`, `notFound()` if missing |
| `/work/[slug]` build | `generateStaticParams()` pre-renders all six |

**To add a seventh case study:** create `content/case-studies/foo.ts`, import
it in `index.ts`, push it into the array, drop screenshots under
`public/images/work/foo/`. Nothing else changes — the grid, detail page,
metadata and static params all derive from the array.

Optional fields worth knowing: `liveNote` (a one-line caveat, clamped to two
lines on cards, shown in full on the detail page) and `demoCredentials` (a
read-only login rendered by `DemoCredentials`, so a client clicking a live
link doesn't dead-end on a login wall).

House rule from `CLAUDE.md`: **never invent metrics.** `outcome` is
qualitative unless a real number was supplied.

## 5. Rendering model — which components run where

Everything is a **Server Component** unless the file starts with
`"use client"`. Server components can be `async` and can hold secrets; client
components ship JS to the browser and can use hooks/state/events.

**Server (no `"use client"`):**
`app/layout.tsx`, all eight `page.tsx` files, both `api/*/route.ts` files,
`ui/Button.tsx`, `ui/Badge.tsx`, `ui/BeamBorder.tsx`, `ui/BackButton.tsx`,
`ui/LiveSiteLink.tsx`, `lib/skill-icons.tsx`, `lib/github.ts`,
`lib/contact.ts`, `lib/quotes.ts`, `lib/views.ts`, all of `content/`.

**Client (`"use client"`):**
`EntrySequence`, `AmbientAudio`, `Nav`, `Footer`, `Toast`, `TypeReveal`,
`DemoCredentials`, `ViewCounter`, `sections/SetupContent`,
`sections/PolicyContent`, every other file in `sections/`, every file in
`case-study/`, `lib/reduced-motion.ts`.

`lib/views.ts` is server-only by construction rather than by directive: it
reads `process.env.KV_REST_API_TOKEN`, which is not `NEXT_PUBLIC_`, so it can
only ever be called from the route handler. The client half of that feature is
`ViewCounter`, which knows nothing but the URL `/api/views`.

Two deliberate choices here:

1. **`Button` stays a server component.** Its hover lift, sheen sweep and
   glow are pure CSS (`.btn-premium` in `globals.css`) precisely so that a
   hover effect doesn't force the hero, every card grid and both footers into
   the client bundle.
2. **`AboutPage` is `async`.** It awaits `getGithubContributions()` on the
   server and passes plain data down to the client `GithubActivity`
   component, so the fetch never happens in the browser.

### The one server-side fetch

`lib/github.ts` hits a public unauthenticated mirror of GitHub's contribution
calendar with `{ next: { revalidate: 3600 } }` — Next caches the response for
an hour. It returns `null` on any failure (non-OK status, network error,
empty payload) and the About page simply omits the section:

```tsx
{contributions && ( <CaseStudySection label="GitHub Activity"> ... )}
```

No error UI, no spinner. A third-party service being down should not put a
broken box on a portfolio.

## 6. The motion system

Three layers, each with a reduced-motion escape hatch.

### Layer 1 — shared variants (`lib/motion.ts`)

Every Framer Motion animation in the app is one of these, imported. **Do not
hand-roll variants in a component** (`CLAUDE.md` convention):

- `fadeUp` — the workhorse: 24px rise + fade.
- `staggerChildren` — parent orchestrator; children use `fadeUp`.
- `scaleIn`, `crossFade`, `slideInLeft` — swap-in-place and chrome.
- `typeContainer` / `typeChar` — per-character typewriter.
- `quoteContainer` / `quoteWord` — per-word blur reveal (hero cover quote).

Two exported helpers matter: `typeDurationMs(charCount)` and
`quoteRevealDurationS(wordCount)`. They **derive** how long a reveal takes
from the same constants the variants use. Anything that must fire "when the
typing lands" (the blinking cursor, the citation fade, the footer's quote
rotation) calls these instead of hard-coding a delay — retune the variant and
the timings follow.

### Layer 2 — the reduced-motion hook (`lib/reduced-motion.ts`)

```ts
export function useReducedMotion(): boolean   // live, updates on OS toggle
```

Built on `useSyncExternalStore`, not `useState` + `useEffect`. Two reasons:
it needs a server snapshot (`false`) to avoid a hydration mismatch, and the
lint rule `react-hooks/set-state-in-effect` rejects the effect version.

The pattern in every animated component:

```tsx
const reduced = useReducedMotion();

<motion.section
  initial={reduced ? "visible" : "hidden"}   // start already-visible
  whileInView="visible"
  viewport={{ once: true, margin: "-80px" }}
  variants={fadeUp}
/>
```

Because the server snapshot is `false`, treat the first render's `false` as
*"unknown"*, not *"motion allowed"*, anywhere it actually matters —
`EntrySequence` reads `matchMedia` directly in a `useLayoutEffect` for
exactly this reason.

### Layer 3 — CSS animation (`app/globals.css`)

Hover sheens, the beam border, the equaliser bars, the drifting heading
gradient. All of it is duplicated inside a
`@media (prefers-reduced-motion: reduce)` block at the bottom of the file
that keeps the colour and drops the movement — plus a blanket safety net that
collapses every transition to 0.01ms.

### The beam border, specifically

`.beam-border` is a conic gradient whose **start angle** is an animated
registered custom property:

```css
@property --beam-angle { syntax: "<angle>"; inherits: false; initial-value: 0deg; }
@keyframes beam-spin { to { --beam-angle: 360deg; } }
```

then masked with `mask-composite: exclude` so only the padding ring paints.
Animating the angle (rather than rotating an oversized square) means the beam
tracks **any** aspect ratio and **any** `border-radius` for free. Usage: drop
`<BeamBorder />` as the last child of any `relative` + rounded element.

## 7. Audio

Two independent sound sources, one shared mute.

```
lib/ambient-mute.ts   ← the shared "sound off" store (sessionStorage)
  ├─ components/ui/AmbientAudio.tsx   the looping background track
  └─ lib/entry-sfx.ts                 the entry sequence's transition blips
```

### The mute store

A hand-written `useSyncExternalStore` store: `subscribeMuted`,
`getMutedSnapshot`, `getMutedServerSnapshot`, `setMuted`. Backed by
`sessionStorage`, wrapped in `try/catch` (private mode throws). Server
snapshot is `false` = sound on.

`sessionStorage` and not `localStorage` **on purpose**: music is part of the
first impression, so a new visit comes up with sound, but a visitor who muted
stays muted for the rest of that visit. Changing this is a product decision,
not a refactor.

### AmbientAudio — three states, not two

```
pending → armed, browser hasn't allowed sound yet ("Tap for sound")
playing → audible                                  ("Sound on")
paused  → visitor switched it off                  ("Sound off")
```

Before the first gesture the control must not claim to be *off* — it isn't,
it's waiting. Browsers block audible autoplay until the visitor interacts, so
the component registers `pointerdown` / `keydown` / `touchend` listeners once
and calls `play()` from the first of them. In practice that first gesture is
the entry sequence's tap.

Details that will bite you if you touch it:

- The `<audio>` element is created **lazily** inside `getAudio()`, so a
  Lighthouse run never fetches the track and the perf budget is unaffected.
- Volume is ramped with `requestAnimationFrame` (`fadeTo`), not cut.
- The first-gesture handler ignores the gesture if it landed on
  `[data-ambient-toggle]` — otherwise the track would start and the same
  click would immediately stop it.
- `visibilitychange` pauses the track in a backgrounded tab.
- If the remote URL 404s or the codec is unsupported, an `error` listener
  sets `unavailable` and the control removes itself.
- `TRACK_SRC` is read from `process.env.NEXT_PUBLIC_AMBIENT_AUDIO_URL` at
  module scope, so it's inlined at build time. **Unset ⇒ the component
  returns `null` and nothing ships.** A fresh clone runs silent, not broken.

**No audio file is ever committed.** It streams from Vercel Blob / Cloudinary
/ Supabase Storage, and it must be licensed (see `README.md`).

### entry-sfx.ts

The blips between name spellings are **synthesised with Web Audio** — a few
oscillators plus one 0.2s noise buffer. Nothing is fetched, so no asset and
no perf cost. `primeEntrySfx()` must be called *inside* the gesture handler
(that's the call that unlocks the `AudioContext`); `playEntryBlip(i)` walks an
ascending pentatonic so six ticks read as one phrase; `disposeEntrySfx()`
closes the context on unmount.

## 8. The entry sequence

`components/entry/EntrySequence.tsx` — mounted in the root layout, so it is
on every route. Six spellings of "Abdus Salam" (English, Hindi, Bengali,
Urdu, Tamil, Telugu) hand off to each other, then the overlay wipes right.

Five things are load-bearing:

1. **It renders identically on server and first client paint**
   (`visible = true`), then a `useLayoutEffect` reads `sessionStorage` and
   `matchMedia` and hides it **synchronously before the browser paints**. A
   `useEffect` here would let returning visitors see it flash in.
2. **Session gate.** `sessionStorage["entry-sequence-played"]`. Once per
   session, not per navigation — a client reopening the link mid-call must
   not sit through it twice.
3. **It waits for a tap** rather than autostarting. That is not a stylistic
   beat: a self-starting intro can only ever play silently, because audio is
   suspended until interaction. The tap is what lets both the blips and the
   ambient track be heard.
4. **Skippable from the first frame** — a Skip button plus tap-anywhere plus
   Escape. Skip *leaves for the site*; it does not fast-forward. Contact
   details must never be more than one click away.
5. **GSAP is dynamically imported** (`import("gsap").then(...)`). A static
   import would put GSAP in the critical bundle for every page view on every
   route, including the ones where the animation never runs.

State shape: `visible` (mounted?), `started` (tapped?), plus `startedRef` —
a ref *as well as* state because the gesture handler and the GSAP build
callback both need the current value synchronously, before a re-render lands.
`playRef` holds `tl.play` so a tap that arrives while GSAP is still loading
still starts the timeline the moment it's built.

## 9. Recurring UI patterns

### Stretched link (used by every clickable card)

A card links to its case study **and** contains a separate "Live site" link.
You cannot nest `<a>` inside `<a>`. So the card is a plain `div` with:

```tsx
<div className="relative ...">
  <Link href={`/work/${slug}`} className="absolute inset-0 z-[1]" />   {/* card link */}
  ...
  <LiveSiteLink className="relative z-[2]" />                          {/* above it */}
</div>
```

Anything that must stay clickable or selectable **inside** such a card needs
`relative z-[2]` — that's why `LiveSiteLink` and `DemoCredentials` carry it
in their own class strings.

Used in: `WorkCard`, `WorkShowcase` (both the preview panel and each list
row).

### Word-wrapping animated text

Framer Motion animates characters/words with `transform`, which needs
`inline-block`, which would otherwise let a line break land mid-word. The fix
appears twice — `TypeReveal` and the hero's `CoverQuote`: group each word in
an `inline-block whitespace-nowrap` wrapper and leave the spaces between
words as **plain text nodes** so the line breaker has legal break points.

### Deriving "animation finished"

`TypeReveal` does **not** use `onAnimationComplete` on the last character —
with the stagger orchestrated by the parent that callback doesn't reliably
report the `visible` variant, which left the cursor and citation stuck at
opacity 0. It uses `setTimeout(typeDurationMs(charCount))` instead.

Also documented in that file: **do not call `usePresence()` in `TypeReveal`.**
It registers the component with the surrounding `AnimatePresence` as
something that must call `safeToRemove()`, and since it never does, the
exiting quote is never unmounted and the footer goes blank after the first
rotation.

### Adjusting state during render instead of in an effect

`Nav` closes the mobile menu on route change with the "previous value"
pattern rather than a `useEffect`:

```tsx
const [prevPathname, setPrevPathname] = useState(pathname);
if (pathname !== prevPathname) { setPrevPathname(pathname); setOpen(false); }
```

One render pass instead of a cascading second one.

## 10. The two API routes

### /api/contact — the contact form

```
ContactForm (client)  --POST /api/contact-->  route.ts (server)  --> Resend --> inbox
      ↑ Toast on success/error                    ↑ validates, holds the API key
```

`app/api/contact/route.ts`:

- Parses JSON with `.catch(() => null)` so malformed bodies don't throw.
- `isContactPayload(body): body is ContactPayload` — a **type predicate**,
  which is how you get from `unknown` to a typed object without `any`
  (banned by `CLAUDE.md`).
- Trims, requires first name / email / message, regex-checks the email.
- Missing `RESEND_API_KEY` → 500 with a friendly message, real error to the
  server log. Resend failure → 502.
- Status codes: 400 bad input, 500 unconfigured, 502 upstream, 200 `{ok:true}`.

`replyTo` is the visitor's address, so replying from the inbox goes to them.
The `from` address is Resend's shared `onboarding@resend.dev` sandbox sender —
swap it for a verified domain if one ever gets set up (note that `CLAUDE.md`
rules out a custom domain for the *site*, which is a separate question).

The client never sees the key — that's the whole point of the route existing.

### /api/views — the visit counter

```
ViewCounter (client)  --GET or POST /api/views-->  route.ts  --> Upstash Redis
      ↑ counts up to the number                       ↑ holds the REST token
```

The footer's total-visit number. `lib/views.ts` talks to Upstash over its REST
API with a plain `fetch` and a bearer token — **no client library and no new
dependency**. The whole store is one key, `portfolio:visits`, and the write is
`INCR`, which is atomic: two visitors landing at once can't clobber each other
the way a read-modify-write against a blob would.

Things that are deliberate:

- **Either env pair works.** The Vercel Marketplace integration injects
  `KV_REST_API_URL` / `KV_REST_API_TOKEN`; Upstash's own integration injects
  `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`. `lib/views.ts` reads
  the first pair and falls back to the second, so the deploy works whichever
  way the store was attached.
- **Unconfigured ⇒ invisible, not broken.** With neither pair set every call
  returns `null`, the route answers `{"visits":null}`, and `ViewCounter`
  renders an empty (but height-reserved) slot, so the footer doesn't shift.
  Same rule as the ambient track. A hard-coded number would be an invented
  metric, which `CLAUDE.md` forbids — no number is the correct fallback.
- **A key that was never written is a real 0**, not a failure. Redis answers
  `null` for a missing key; `redis()` maps that to `0` and reserves `null`
  for genuine errors.
- **One visit, not one page view.** `ViewCounter` gates on the `visit-counted`
  sessionStorage key — the same idea as the entry sequence's gate. Already
  counted ⇒ `GET`; first page of the visit ⇒ `POST`. If storage throws
  (private mode) it assumes *counted* and sends `GET`, so the failure mode is
  undercounting rather than counting one person on every navigation.
- **`export const dynamic = "force-dynamic"`**, plus `cache-control: no-store`
  on the response and `cache: "no-store"` on the fetch. A cached counter is a
  wrong counter, at every layer.
- **The number rolls up rather than snapping** (and snaps under reduced
  motion). Screen readers get the settled figure from an `sr-only` span
  instead of the ticking digits.

**If you add anything that stores or counts, update `content/privacy.ts` in
the same commit.** It names the sessionStorage keys and the third parties one
by one, and its own header comment says as much.

## 11. Design tokens

All in `:root` in `app/globals.css`. **Dark theme only** — no light palette,
no toggle, no `dark:` variants, no `lib/theme.ts`. Deliberate (see
`CLAUDE.md`); do not reintroduce it.

| Token | Value | Use |
|---|---|---|
| `--background` | `#050806` | near-black, nudged green |
| `--foreground` | `#eaf2ec` | body text |
| `--surface` | `#0c110d` | raised card ground |
| `--accent-deep` | `#00b140` | flag green from the cover art |
| `--accent` | `#22c55e` | borders, beams, glows |
| `--accent-bright` | `#4ade80` | **text** — clears 12:1 on the background |
| `--accent-soft` | `#86efac` | hover text |
| `--gh-level-0…4` | | GitHub calendar squares |

**Rule: accent text uses `--accent-bright`, never `--accent`.** The deeper
two don't hit contrast. `.text-accent-glow` and `.text-gradient-accent` both
honour this.

Hand-written CSS component classes worth knowing (all in the
`@layer components` block): `.beam-border`, `.text-accent-glow`,
`.text-gradient-accent`, `.surface-accent` (the shared card ground),
`.accent-bloom`, `.btn-premium` + `.btn-primary` / `.btn-ghost` +
`.btn-shine`, `.link-underline` (set `data-active="true"` to hold it open),
`.eq-bar`.

The fixed green wash behind everything is `body::before` — three radial
gradients, `position: fixed` so it reads as light in the room rather than a
gradient that scrolls away.

## 12. Env, commands, deploy

`.env.local` (never committed; `.env.example` documents both):

```
RESEND_API_KEY=                   server-side, contact form
NEXT_PUBLIC_AMBIENT_AUDIO_URL=    client-side (NEXT_PUBLIC_ = shipped to browser)
```

Attach the Redis store from the Vercel dashboard (Storage → Create → Upstash
Redis) and the last two are injected into every environment for you;
`vercel env pull .env.local` brings them down locally. All four are optional —
leaving one unset just switches its feature off (no email, no music, no
counter).

```bash
npm run dev     # local
npm run build   # must pass with ZERO TypeScript errors before a phase is "done"
npm run lint    # must pass too
```

Deployed to Vercel on a `*.vercel.app` subdomain. No custom domain — client
decision. Both env vars must also be set in the Vercel project settings.

## 13. Gotchas / things that look like bugs but aren't

- **`LayoutProps<"/">` in `app/layout.tsx`** is not imported. Next 16
  generates it into `.next/types` and `tsconfig.json` includes that path.
- **`process.env.NEXT_PUBLIC_AMBIENT_AUDIO_URL` is read at module scope** in
  `AmbientAudio`, above the component. That's what makes the "unset ⇒ nothing
  ships" behaviour work; moving it inside the component breaks it.
- **`AmbientAudio` returns `null` before calling a hook.** That's legal here
  only because the early return lives in the outer `AmbientAudio` wrapper and
  all hooks live in the inner `AmbientAudioPlayer`. Don't merge the two.
- **`getSkillIcon` returns `undefined` on purpose** for techs with no official
  brand mark (Firecrawl, Recharts, Thunder Client, Catppuccin). They render as
  plain text; no generic substitute icon. VS Code is the one entry not from
  Simple Icons — it comes from react-icons' `vsc` set, which carries the real
  product mark that Simple Icons doesn't ship.
- **`/api/views` answering `{"visits":null}` is not a bug.** That's what an
  unconfigured or unreachable Redis store looks like, and the footer correctly
  renders nothing. Check the env vars before debugging the route.
- **`/gear` is reachable but unlinked.** `content/gear.ts` exports an empty
  array, so `hasGearContent` is false and the footer omits the link; the page
  says plainly that it isn't written yet. Filling in `GEAR_SECTIONS` is the
  only step needed to publish it.
- **`eslint-disable-next-line react-hooks/exhaustive-deps` in `TypeReveal`** is
  intentional and commented — callers pass an inline arrow for `onComplete`,
  which would restart the timer every render.
- **`BeamBorder`'s glow is dimmed with `filter`, not `opacity`** — the
  `hoverOnly` variant already animates `opacity`, and the two would cancel.
- **Case study images are `.webp` under `public/images/work/<slug>/`.** They're
  local, so `next.config.ts` needs no `remotePatterns`.
- **`bob.png` and the three `Screenshot ….png` files at the repo root** are
  stray working files, not referenced by any import.
